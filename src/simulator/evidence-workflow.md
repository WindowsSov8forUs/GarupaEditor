# Simulator 原作算法对齐规范

本文件定义实际要求、验收边界和执行流程。通用约定见[AGENTS.md](../../AGENTS.md)，行为与来源见[rendering-consumption-contract.md](rendering-consumption-contract.md)，已有能力声明见[public/capabilities.ts](public/capabilities.ts)。当前进度只维护在本地任务摘要；本规范不自动改变已有能力状态或证据结论。

## 1. 目标与范围

“明确无算法差异”指：Simulator 当前已承载的功能，在明确的原作版本与合法输入域内，计算规则、状态变化及生产输出语义与原作一致。目标是修复产品算法，不是在 Tauri/Pixi 中复刻 Unity 引擎。不能把“尚未发现差异”当作已验证一致，也不能把尚未验证的引擎细节全部算作算法错误。

范围以现有公共入口、能力合同和实际生产消费者为准，不自动增加功能，也不得通过删除消费者、缩小合法输入域或改写能力声明来消除待修问题。每项须落到具名消费者和验收条件，不能只写“全部生命周期”或“完整渲染链”。

| 功能域 | 必须对齐的实际语义 |
| --- | --- |
| 谱面与时间 | 原作兼容域内的时间换算、事件顺序、播放/暂停/恢复及练习定位；产品扩展按自身合同分开验收 |
| 音符与输入判定 | 音符运动、轨道投影、输入匹配、判定窗口、长条/滑条状态和几何 |
| 计分与游戏状态 | 分数、连击、Life、结束条件及已支持模式间的状态变化；保留计分合同明确的例外 |
| 粒子与演出 | 已使用配置的产生/更新/销毁、随机数归属、时间推进、变换、颜色、UV、几何及影响输出的播放/预热行为 |
| 场景与绘制 | 实际对象的坐标、可见性、裁剪、遮挡顺序，以及材质颜色、混合和剔除的最终语义 |
| HUD与媒体 | 分数文本、布局、缩放和裁剪规则；音频/MV的触发、选择及时间同步语义 |

此表是功能分类，不是新的完成声明或功能授权。既有排除项与 Garupa 扩展见[README.md](README.md)及各能力合同；不将扩展强行改成原作行为。

## 2. 平台适配与调查边界

允许使用 Tauri、Pixi、WebAudio 和浏览器的对象、缓存、资源管理及绘制方式。内部结构、API、枚举值和执行步骤可以不同，但必须保留范围内的计算与输出语义。

- 不要求复制 Unity 的对象注册表、内存布局、分配器、缓存驻留、线程调度、GPU提交或驱动实现。只有存在通向范围内输出的具体依赖时，才调查必要部分。
- 配置或枚举不同先记为候选。例如原作 Cull=2、产品关闭剔除，须结合几何、坐标翻转和实际消费判断是否造成语义差异，不能直接照搬状态或认定画面错误。
- 字体缓存未驻留某数字、运行对象地址未绑定、任意引擎分支未覆盖，不自动成为阻塞。静态指令与序列化关系能充分确定规则时，不强制追加运行态观察；必要动态输入无法确定时，才保留具体缺口。
- 不以补齐所有字形、所有材质变体、全部引擎调用或输入笛卡尔积为独立目标。范围内实际支持的分支仍须有依据，不能以节省资源为由跳过会影响产品行为的分支。
- 不要求 Unity/GPU逐像素、字体栅格器、物理音频或固定设备输出完全一致。几何、颜色公式、排序、裁剪等已有算法错误不能借“平台适配”排除。
- 平台适配须说明原作语义、产品实现及保持语义的依据；未验证的行为变化不能直接标记为适配。

## 3. 分类与完成条件

| 状态 | 判定依据 | 行动 |
| --- | --- | --- |
| 已确认算法差异 | 在可对应的输入下，原作规则/输出与实际生产消费者的语义不一致 | 优先修复并验证受影响链路 |
| 待验证候选 | 配置、结构或局部实现不同，尚未证明输出语义不同 | 先做最短的相关性核查，不计入已确认错误数 |
| 必要证据缺口 | 无法确定某项范围内行为所需的规则、输入或消费关系 | 明确阻塞哪项验收，只补必要证据 |
| 范围内一致 | 指定输入域的规则及生产消费已有充分对照 | 复用结果；相关依赖变化时重验 |
| 平台适配/范围外 | 语义保持的实现差异，或既有合同明确排除的能力 | 记录理由，不列为算法修复阻塞 |

单项完成必须同时满足：原作依据可追溯；正常路径、影响语义的分支和边界已核对；实际生产消费者正确承接结果；已发现差异归零；适用验证通过。可以通过静态推导、已有独立原作输出及差分审计组合完成，不要求每项都新增运行采样或测试工具。

整体完成必须列出当前功能范围，并确认每项已完成，范围内没有未解决的已确认差异或必要证据缺口；候选均已判定，平台适配有依据。不能凭编译通过、提交数、样本数或局部零差异宣称整体完成。结论应写成“在所列功能与输入范围内无算法差异”，同时列出适配与既有排除项，不承诺整个 Unity 或任意未来输入等价。

## 4. 按问题推进，限制扩查

每阶段只记录四项：具体问题、生产消费者、必要依赖、关闭条件。先复用已有来源和验证，定位第一处分歧，再补修复所需证据。优先完成已确认差异；候选先判断相关性；无关发现仅登记，不自动展开。

二进制逆向优先使用 `ida-pro-mcp`，从具名函数开始，按需展开汇编或引用。不默认导出整个组件，不因能读取某个运行对象就启动对象树扫描。

- 每次扩查前说明它会决定哪个生产行为、会如何影响修复。说不清时停止该支线，回到当前问题。
- 每60分钟复核是否产生可用结论或生产修复。连续取证仍不能决定修复时，缩短问题、换方法或报告精确阻塞；不靠切换无关支线维持工作。
- 工具失败先保留原因与已完成边界；同一失败不连续重复尝试。只有出现新的定位依据并完成可行的离线检查后才考虑一次重试，且遵守用户更严格的限制。
- 不要求用户重复进入场景、登录或补齐样本，除非确实缺少关闭当前问题所必需的输入。既有授权持续有效，不重复请求。
- 时间估计依据剩余具体问题和不确定性，不按证据、提交或文件数量计算百分比。明确区分生产修复、确认一致、工具维护和证据补充。

## 5. 证据与最小验证

原作行为依据来自[GirlsBandParty-Reverse](https://github.com/WindowsSov8forUs/GirlsBandParty-Reverse)已验证、已提交、已推送的证据；当前锁定10.1.4/230 ARM64。区分静态指令、序列化事实、动态观察、数值输入假设和推断。expected独立来自原作，不能由产品生成。算法修复不依赖录屏、截图、framebuffer或视觉调参。

| 改动 | 必要验证 |
| --- | --- |
| 生成器、源绑定或原始输入 | 对应再生成/字节比对、摘要清单和仓库政策；共享代码影响旧模式时验证旧模式 |
| 差分审计器 | 对同一独立expected验证受影响消费者；未变生成器的原作输出可复用 |
| 生产算法 | 对应原作差分或有充分依据的源级对照、受影响消费链、适用TypeScript与运行合同检查 |
| 文档或状态 | 内容、引用、diff和仓库政策；不运行编译、应用或无关算法审计 |

复用已有工具与报告。验证记录绑定原作提交/输入、产品源码及相关依赖、工具版本、结果和边界；相关依赖变化才重验对应部分，依赖不明时做针对性核查，不默认重跑全部。不开新框架，不反复复制完整资源树，不为覆盖计数制造新样本。

本轮禁止新增、修改或生成产品测试、fixture、snapshot、harness，含ignored和临时文件；不运行应用或视觉验收。允许Reverse原始提取器、字节验证器及只消费native/serialized expected的独立审计，但同样受最小必要范围限制。改变限制须用户明确授权；已授予的具体例外按其范围执行。

未知语义按[运行失败政策](../runtime-contract-policy.md)处理，不用默认值、静默降级或无界clamp掩盖，也不因研究未完成或 `evidence-required` 拒绝合法动作。评分例外见[scoring-contract.md](scoring-contract.md)。

## 6. 交付、记录与资源

1. 新增Reverse证据先验证、精确暂存、检查、提交、推送并确认远端同步，再由Garupa正式消费；已有已交付证据直接复用，不制造空提交或重复握手。canonical dirty checkout保持只读。
2. 一个问题完成一次交付，相关生产修改、说明与验证归入同一意图；不为每次工具调用、样本或只读观察单独提交推送。无差异就登记一致，不为提交而重构。
3. 稳定规范只放规则，生产合同只放行为、来源、消费者及验证边界。当前任务摘要维护唯一待办，验收摘要维护验证与交付，证据指针维护定位；历史归档不作为当前待办自动执行。
4. 默认一个重型进程，无用户或适用规范要求不启动子代理。输出默认约100行/4KB以内；大文件只读所需字段，完整报告存文件。及时释放本任务不再使用的重型进程，不干预其他进程。
5. 更新只报告新增事实、阻塞和下一步；交付报告说明实际修复、验证范围和剩余问题，不将工具维护计作算法修复。

生产不读取Reverse、`tmp/`、`testing/`或未登记证据。维护工具使用显式参数或 `GARUPA_REVERSE_ROOT`，宿主绝对路径不写入tracked文件。保留唯一入口、Recipe13、transport3、资源所有权与既有能力合同。历史type-5 `+Y`和current native `+Z`的来源身份分别保留；Fixture manifest继续拥有快照身份，未获授权不改写快照、锁文件或无关模块。
