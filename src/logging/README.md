# 应用日志

使用 Tauri 官方 `tauri-plugin-log` 统一接收原生端和各 WebView 的日志。文件写入与轮换交给插件；前端批量转发由原生阻塞任务池处理，不在渲染线程写文件。

- Windows：`%LOCALAPPDATA%/com.garupa.editor/logs/application.log`。其他平台使用 Tauri 的 `app_log_dir`。
- 每份文件上限 4 MiB，保留 5 份历史文件及当前文件；无自动上传。
- 每条应用事件包含时间、等级及事件名。前端另含窗口角色、会话 ID；耗时操作有操作 ID 和持续时间。
- 正常情况下前端最多缓冲 500 ms，错误立即尝试刷新。队列上限 256 条，重复警告/错误在 5 秒内合并；丢弃/抑制计数以 `logger.suppressed` 记录。异常退出可能丢失尚未发送的末尾记录。
- 自动保存成功至多每类每 30 秒记录一次；不记录逐帧渲染、触摸流或媒体分块成功事件。

## 接入

宿主代码使用 `appLog`、`startOperation`；原生调用使用 `loggedInvoke`，不绕过它直接调用 Tauri `invoke`（日志传输自身除外）。Simulator 通过无宿主依赖的 `diagnosticEvent` 发送生命周期诊断，未接入日志时不影响计算。

只传事件所需的资源 ID、槽位、状态、计数和耗时。禁止传整个命令参数、响应、谱面、媒体或账号对象。日志层限制长度和深度、脱敏敏感字段、移除 URL 查询和片段；账号调用不记录响应错误详情。脱敏不是允许随意传入敏感对象的理由。

已接入启动与未处理异常、前端警告/错误、全部现有原生调用入口、目录刷新/回退、资源获取及快照失败槽位、资源记录损坏、导入导出操作、缓存恢复和自动保存、设置应用、皮肤与缩略图、静态预览及 Simulator 启动/控制命令/最终关闭故障。

排查问题时提供当次运行的 `application.log`，若发生轮换再附对应历史文件。文件目录快照不能替代运行日志；日志本身也不证明算法或视觉等价。
