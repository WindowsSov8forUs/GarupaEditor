# Shared chart formats

`src/chart` owns application-wide serialized chart schemas and pure format conversion utilities.

- `garupa.ts`: canonical Garupa chart JSON schema. Besides BPM/SV/notes/Slide, it carries the chart header `{"type":"Header","data":"#HABAHIRO"}` (no beat, at most one; the original `#HABAHIRO` header) and the timed command `{"type":"System","beat":…,"data":"#LANE_CHANGE"}` (several allowed; as in the original converter the latest beat sets the change position; requires the HABAHIRO header). Notes wider than one lane, except Directional, require the HABAHIRO header. Bestdori V2 export drops both items.
  - Slide gesture nodes (extension). The original game only places flicks on a Slide's last node (Flick, Directional and Multiple-Directional tails). Garupa additionally allows a `Flick` or `Directional` connection as a Slide's head or an intermediate node: a gesture the player must complete at that point of the Slide before it continues. The simulator marks such nodes with `slideGesture` (Flick → judge type 3; Directional width 1 → 9; wider Directional → 10 with the width as its directional count). A Directional of width w > 1 also carries an exit offset of ±(w−1) lanes, so the Slide continues from the far end of the arrow. Pressing a gesture head only binds the touch; it is judged on movement with the same contact, grace, direction and distance gates as a flick tail, and an intermediate gesture re-bases the origin when the hold reaches it. Last nodes never carry `slideGesture`: Flick/Directional tails convert to the original tail types and follow the original tail path.
- `bestdori-v2.ts`: canonical Bestdori V2 chart JSON schema used by import/export flows.
- `conversion.ts`: parsing, optional BPM-zero normalization, and Garupa ↔ Bestdori V2 conversion. Canonical optional `timingGroup` fields are omitted when absent/Global rather than emitted as own `undefined` properties; BPM-zero normalization preserves Slide owner groups.
- `index.ts`: the public module surface.

This module must stay independent from React, Tauri, simulator runtime types, skin resources, and editor controller state. `src/chartCore.ts` retains the editor's internal `ChartNote` model and editor/display-oriented operations; serialized format types do not belong there.

Chart metadata no longer embeds Data URLs or remote URLs. BGM, cover, MV and stage backdrop are main-program `ResourceRef` values persisted separately in `chart-resources.v5.json`; portable Garupa/Bestdori chart schemas remain resource-independent. User and provider-downloaded chart media belong to the recoverable current-session workspace, while Builtin/default Skin refs remain application resources. The one-time v2/v3/v4 migration adopts provable bytes/refs into workspace records; an ambiguous identity leaves that migration action unavailable while preserving durable data and never substitutes a default.
